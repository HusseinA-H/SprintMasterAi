Module 3

Granular Task Execution

Dependencies
Tasks can depend on previous items; prompts enforce dependency tracking.
Time Logging
Every task features an estimated duration (e.g. 1.5h), supporting daily scheduling.
Prioritization
Tasks are tagged Low, Medium, or High, indicating clear focus areas.

Task state mutations are done with PATCH REST endpoints, immediately updating database fields.

AI Features

Custom Planning Engine

Prompting Strategy
Instructs LLM to return valid JSON with strict schema validation. Excludes conversational clutter.
Scale & Normalize
Deterministic algorithm clamps tasks to 0.5h-8h and scales them to fit the 1-24h day budget.
Alternative Paths
Pro-tier option accepts historical logs and instructs Groq to build different execution models.
Atomic Rollbacks
Failures during task creation trigger immediate deletions of partial DB objects.

System Design

Decoupled Monorepo Architecture

Decoupling static presentation elements from heavy API and database layers ensures resilience and high loading speeds.

Vite SPA Frontend (Vercel CDN)
    │
    ▼ (HTTPS REST / CORS / Cookies JWT)
Next.js 15 Backend API (Docker Node Server)
    ├─► Payload CMS Core Controller (Access Control Hooks)
    ├─► MongoDB Atlas Database (Mongoose Layer)
    └─► Groq AI / SMTP Mail Adapters (Resend API)
Database Design

Collection Schema Mapping

Users
- email (unique)
- subscription
- role (user/admin)
- sprintCount (cached)
- generationAttempts
Sprints
- title (req)
- description
- goal (req)
- status
- estimatedHours
- createdBy (ref Users)
Tasks
- title (req)
- duration (text)
- priority
- dependsOn (json)
- completed
- sprint (ref Sprints)

Collections use Payload joins for efficient population, reducing lookup request frequencies.

Security

Enterprise Security Standards

Stateless JWT
Sessions are verified using secure JSON Web Tokens stored on the client and in browser cookies.
Row-Level Access (RLS)
Database operations evaluate document ownership, restricting read/update scopes automatically.
Bcrypt Encryption
Passwords are encrypted at the database level. Direct passwords are never stored.
Dual-Tier Validation
Double validated via Zod on the frontend and Payload mongoose schema verification on the backend.
